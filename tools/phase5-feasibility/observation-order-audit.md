# 공개 관측 순서·시점 감사

## 판정

`ProtagonistObservation`의 원천인 `PublicInformation`과 공개 `PhaseLogEntry`는
이제 같은 `(loop, day, phase, sequence)` 순번을 사용한다. 역할 공개에는 공개 순간의
`PublicObservationContext`도 보존한다. 구 저장처럼 이 정보가 없는 관측은 새 시점
규칙의 배제 근거로 쓰지 않는다.

`paranoiaVirus`는 배정 역할과 공개 순간의 유효 역할이 달라지는 유일한 현재 규칙이다.
일반 캐릭터의 역할 공개를 다음처럼 판정한다.

| 공개 역할 | 공개 순간 불안 | `paranoiaVirus` 조합 판정 |
|---|---:|---|
| `person` | 0~2 | 모순 아님 |
| `person` | 3 이상 | 모순, 조합 배제 |
| `serialKiller` | 0~2 | 바이러스 변이로 설명 불가 |
| `serialKiller` | 3 이상 | 기본 `person`의 변이로 설명 가능 |
| 어느 역할이든 | 시점 상태 없음 | 새 배제 없음 |

역할표는 공개된 `serialKiller`를 곧바로 배정 역할로 확정하지 않는다. 불안 3 이상이면
기본 `person`일 수 있고, `hiddenFreak`도 남아 있으면 기본 `serialKiller`일 수도 있다.
따라서 가능한 기본 역할의 합집합만 남긴다.

## 전수 확인 결과

현재 `effectiveRole()`을 바꾸는 규칙은 `paranoiaVirus` 하나뿐이다. 역할·룰 조합·사건
필터가 사용하는 모든 `ProtagonistObservation` 종류와 원천을 확인한 결과는 다음과
같다.

- **추가 축소가 가능한 실제 누락:** 역할 공개 시점의 불안과
  `person`/`serialKiller` 공개. 이번 변경에서 필터와 역할표에 반영했다.
- **실제 날짜가 잘못 남던 누락:** AI 사건 해결 관측은 예정 사건일 `day`가 아니라
  실제 해결일 `resolvedOnDay`를 우선 사용한다. 현재 이 관측은 보수적으로 후보를
  줄이지 않지만, 후속 결합 추론의 시간축을 바로잡는다.
- **이미 시점 상태를 사용하던 관측:** 사건 발생·미발생, 패배, 각본가 능력 결과,
  음모 금지 무시는 각각 판정 직전/완료 시점 공개 보드를 가지고 있다. 장소 조건,
  위치 교집합, 사망 원인 후보 등 기존 축소는 이 스냅샷이 있을 때만 수행한다.
- **순서를 더 알아도 현재 단독으로 안전하게 줄일 수 없는 관측:** 우호 능력
  수락·거부, 공개 범인, 룰 X 공개, 역할 미공개 사망. 이들은 정적 역할 제약이거나
  이미 공개된 직접 사실이며, 추가 상태 없이 앞뒤 순서만으로 새 모순을 만들 수 없다.
- **완전 trace에서만 보존하는 신호:** P2/P3의 뒷면 카드 대상·소유자·배치 순서와 P4
  공개 순서. 이는 전략적 시그널링에는 중요하지만 현재 규칙 가설 필터의 확정 배제
  근거는 아니다.

공개 시점 상태가 없거나 두 기본 역할이 모두 가능한 경우에는 후보를 유지한다. 이는
새 규칙이 과잉 배제를 일으키지 않도록 하는 보수적 경계다.

## 회귀 범위

- 불안 2에서 `person` 공개: 바이러스 조합 유지
- 불안 3에서 `person` 공개: 바이러스 조합 배제
- 공개 순간 상태가 없는 구 관측: 바이러스 조합 유지
- 번들 `basicTragedy:4`에서 각본 `person`인 회사원이 불안 3에서 실제 P6 능력으로
  `serialKiller`를 공개: 실제 룰 조합이 룰 필터와 역할표 양쪽에 남음
- 하나의 P6 해결에서 역할 공개와 우호 해결 기록이 공유 순번 0, 1로 수집됨
