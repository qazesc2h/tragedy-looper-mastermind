# 패배 조건 실제 위험 경로와 각본가 화면 감사

- 실행일: 2026-08-21
- 범위: 지시 순서 1·2 (`distanceToLoss` 위험 경로, 화면 표시)
- 계측 코드: `tools/phase5-feasibility/audit-distance-to-loss-contracts.ts`
- 수정 코드: `src/engine/loss.ts`, `src/ui/mastermind-panel.ts`,
  `src/ui/main.ts`, `src/ui/styles.css`

## 판정 구조

실제 패배 판정용 `LossDistance`는 기존 timing·activation·`met` 계약을 유지한다.
`evaluateLoss()`와 P9 선택 발동은 이 종착 조건만 사용한다. 여기에 화면·전략 소비자가
읽는 `routes`를 추가했다. 한 경로는 다음을 별도로 보존한다.

- 경로 key와 명칭
- 자동 / 각본가 선택 / 주인공 선택
- 발동 시점과 사건까지 남은 날짜
- 현재 경로의 사용 가능 여부
- 개별 요구조건의 `current`, `needed`, `remaining`, `met`

화면은 최상위 `remaining` 합계와 하나의 진행 막대를 더 이상 표시하지 않는다. 각
경로를 별도 카드로 만들고 요구조건별 충족 여부와 값을 나열한다. 경로의 `요구 X/Y`는
가중 점수나 최적 판정이 아니라 표시된 요구조건 중 현재 충족된 개수다.

## 보호 캐릭터 사망 경로

현재 각본에 실제로 존재하는 다음 경로만 만든다.

- 살인 청부업자: 실제 능력 보유자 생존, 핵심 인물 음모 2, 같은 장소/세력권,
  대상 생존·보호 없음·사망 가능
- 연쇄 살인마: 대상과 같은 장소, 같은 장소의 다른 생존자가 정확히 1명,
  대상 생존·보호 없음·사망 가능
- 사건:
  - 자살: 범인 자신
  - 살인 사건: 범인과 같은 장소의 다른 캐릭터 중 각본가가 선택
  - 원격 살인: 음모 2 이상인 캐릭터 중 각본가가 선택
  - 병원 사건: 병원 음모 1 이상일 때 병원의 모든 캐릭터
- 이세계인 우호 4: 주인공 선택 경로로 분리. 생존·우호 4·동소·이번 루프 미사용을
  개별 표시

모든 사망 경로는 보호 카운터와 시간 여행자 사망 면역을 함께 검사한다. 사건 경로는
범인 생존·불안 한계·발생 억제·검은 고양이 효과 억제·예정일 경과 여부를 표시한다.

살인 청부업자의 `LossDistance` 카드도 두 경로를 분리한다.

1. 청부업자 본인 음모 4 → 주인공 사망
2. 핵심 인물 음모 2 + 같은 장소/세력권 → 핵심 인물 사망

`lovedOne`과 주인공 사망 `hospitalIncident`는 각 요구조건을 별도 행으로 표시한다.
최상위 합산 `remaining`은 판정 호환용 필드로 남아 있지만 UI와 경로 요약은 읽지 않는다.

번들 47개 난이도의 초기 상태에서 `distanceToLoss()`를 실제 호출했다.

알려진 경로가 0개인 보호 조건은 `basicTragedy:7`의 친구 역할 이세계인 한 건이다.
이 각본에는 연쇄 살인마나 이세계인을 죽일 사건이 없고, 6일 살인 사건의 범인이
이세계인 자신이라 자기 자신을 대상으로 고를 수 없다. 화면은 이 경우
“현재 각본에서 확인된 사망 경로 없음”을 표시한다.

`be207dc36caab8e05effb97e73ef8ba91fcce017f81928d4cc4a510dd9e5336e`였고,

## 실제 화면 검증

390×844 인앱 브라우저에서 두 상태를 확인했다.

- 저장된 기본편 상태: 봉인된 것, 친구의 연쇄 살인마·자살 경로, 연인A의 불안·음모
  요구조건이 분리됨
- 격리된 `firstSteps:2` 새 게임: 핵심 인물 아래 청부업자·연쇄 살인마·3일 자살,
  살인 청부업자 아래 주인공 사망·핵심 인물 살해가 분리됨

`firstSteps:2`에서는 패배 판정 카드 2개, 실제 경로 5개, 요구조건 행 25개를 렌더링했다.
문서와 각본가 패널 모두 `scrollWidth === clientWidth`였고 브라우저 오류는 0건이었다.
