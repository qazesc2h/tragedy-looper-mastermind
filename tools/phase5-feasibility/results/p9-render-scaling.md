# `못된 고양이` P9 렌더 증가 측정

2026-08-31에 390×844 브라우저에서 실제 엔진 진행으로 `못된 고양이`의 각 루프
5일차 `P9_ROUND_END`에 진입했다. 각 대상 루프의 현재 보드에는 같은 스트레스
카운터를 적용하고, 앞선 루프의 공개 관측과 진행 기록은 버리지 않았다. 각 수치는
새 브라우저 문서에서 3회 측정한 중앙값이다.

| 현재 루프 | 공개 관측 | 전체 렌더 | DOM 원소 | HTML bytes |
|---:|---:|---:|---:|---:|
| 3 | 43 | 544.8ms | 2,805 | 176,577 |

관측은 루프마다 15개씩 선형으로 늘었지만 전체 렌더는 3→4루프에서 1.80배,
4→5루프에서 1.64배가 됐다. 이 표본은 선형 증가가 아니며 관측 수 제곱에 가까운
증가를 보인다. 5루프 마지막 날 1.6초는 단계 전환 UI에 그대로 둘 수 있는 비용이
아니므로 추가 대책이 필요하다.

## 현재 지연 계산 경계

각본가 오버레이가 켜져 있으면 다음은 패널이 접혀 있어도 항상 계산하거나 전체
HTML을 만든다.

- 역할·룰 고정점, 관측별 룰 배제 수, 과거 패배별 prefix 재평가
- 역할 후보와 사건 범인 후보, 접힌 추론 과정, 전체 역할·범인 격자
- 접힌 각본가 지침 A~E의 계산과 본문
- 접힌 과거 루프·날짜를 포함한 진행 기록 본문
- 남은 룰 조합 목록과 관측 근거 본문

다음 예고는 현재 단계와 조건이 맞을 때만 계산한다.

- 현재 루프 종료 예고: 마지막 날 P9 또는 종료 대기 상태
- P9 선택 훅·선택 패배 예고: 해당 P9 선택지가 표시되고 필요한 대상이 정해진 때
- P5 능력 예고: 해당 P5 훅 선택지가 표시된 때
- P6 우호 거부 예고: 해당 P6 우호 능력 선택지가 표시된 때

즉 현재 단계와 무관한 P5/P6/P9 예고를 항상 미리 계산하는 문제는 없다. 가장 큰 남은
비용은 접힌 룰·추론·지침 본문까지 즉시 만들고, 과거 패배 prefix를 매 렌더마다 다시
평가하는 경로다. 우선순위는 prefix 결과의 증분 또는 상태 캐시이며, 그 다음이 접힌
본문의 지연 렌더다.

## 관측 캐시 정확성

교차 관측 캐시는 전체 가설 결과가 아니라 역할 원인 고정점의 조합별 결과만 저장한다.
키는 `JSON.stringify([tragedySet, publicCast, relevantObservations])`이며, 필터를 통과한
각 관측 객체 전체를 직렬화한다. 따라서 관측 본문의 `loop`·`day`·`timing`과
`observedAt.loop/day/phase/sequence`, 그리고 `context.locationIntrigue`와 관측 시점
캐릭터의 장소·불안·음모·우호·생사 상태가 모두 키에 들어간다.

같은 능력 결과라도 학교 음모가 0/2인 경우와, 같은 P9 쌍 사망이라도 생존자의 불안이
2/3인 경우를 한 프로세스에서 차례로 평가하는 회귀 테스트를 추가했다. 앞 호출의 캐시를
공유했다면 뒤 호출이 잘못 배제되지만 두 경우 모두 관측 시점 상태에 맞는 결과를 냈다.
도심 음모도 같은 `locationIntrigue` 객체에 있으므로 관련 관측의 키를 분리한다.

`lossObserved`처럼 교차 역할 원인 고정점에 영향을 주지 않는 관측은 이 캐시에서
의도적으로 제외된다. 해당 관측의 패배 조건·도심 음모 판정은 캐시된 하위 계산이 아니라
매 `evaluateRuleHypotheses()` 호출의 직접 판정 경로에서 다시 계산한다.

## 224개 경로의 의미

224개는 전체 난이도 감사에서 집계한 정적 인과 경로 계약이다. 한 P9 상태에서
`distanceToLoss()`가 직접 순회하는 경로 수가 아니다. 런타임은 선택된 시나리오에
해당하는 조건과 경로만 반환하며, 이번 `못된 고양이` 상태에서는 2개였다.

## 1차 개선 — 과거 패배 prefix 세션 캐시

2026-08-31에 같은 390×844 재현 경로를 다시 측정했다. 완료된 날짜의
`roundEvidence`에 증거 확정 순번을 기록해 이후 루프가 추가돼도 과거 관측 prefix가
달라지지 않게 했다. 캐시는 `tragedySet + publicCast + 관측 객체 전체 + 후보 조합 ID`
가 정확히 같은 경우만 재사용한다. 후속 관측과 후보 집합이 달라지면 역할표 고정점과
룰 배제 매핑을 다시 계산한다.

| 현재 루프 | 공개 관측 | 전체 재계산 prefix | 세션 캐시 prefix | 개선 전 전체 렌더 | 개선 후 전체 렌더 |
|---:|---:|---:|---:|---:|---:|
| 3 | 43 | 39.2ms | 0.2ms | 544.8ms | 309.2ms |
| 4 | 58 | 74.1ms | 0.3ms | 980.5ms | 535.8ms |
| 5 | 73 | 126.0ms | 0.2ms | 1,612.0ms | 854.1ms |

각 값은 새 브라우저 문서 3회의 중앙값이다. prefix 캐시 비용은 관측 수와 무관하게
측정 해상도 수준으로 유지됐고, 전체 렌더는 각각 43.2%, 45.4%, 47.0% 줄었다.
전체 재계산 기준선도 한 역할표 빌드 안에서 관측 불변 전처리를 공유하고 중복 초기
역할표 생성을 제거해 개선 전 prefix 비용보다 작아졌다.

가설 결과나 prefix 캐시는 localStorage에 저장하지 않는다. 모듈 세션 메모리의 LRU
8개 컨텍스트, 컨텍스트당 최대 512개 prefix 노드로 제한했다. 저장되는 새 필드는
가설 결과가 아니라 `roundEvidence`가 더 이상 바뀌지 않는 실제 공개 관측 순번뿐이다.
구 저장처럼 관측 순번이 불완전한 데이터는 기존 수집 순서를 유지하므로 서로 다른
prefix를 잘못 공유하지 않는다.

이 개선으로 과거 패배 prefix의 제곱 증가는 제거됐지만 전체 렌더는 아직 선형이 아니다.
개선 후 3→4루프는 1.73배, 4→5루프는 1.59배이며 5루프 854.1ms로 200ms 목표를
넘는다. 현재 상태 자체의 역할표 계산이 3/4/5루프에서 각각 209.4/417.3/714.9ms로
남은 주 병목이다. 다음 단계에서 접힌 패널의 역할표·추론 본문 계산 및 DOM 생성을
실제로 펼칠 때까지 미뤄야 한다.

## 2·3차 개선 — 접힌 본문 계산·DOM 지연

접힌 패널은 요약에 필요한 값과 본문을 분리했다. 정확한 룰 후보 `105 → N`과 현재
P9 공개 예고는 현재 단계의 핵심 정보라 계속 계산한다. 반면 정확한 역할 확정 수는
역할표 전체가 필요해 싼 요약이 아니므로, 역할·범인 패널은 접혔을 때 `펼쳐서 계산`만
표시한다. 역할 후보·사건 범인 후보·추론 과정·전체 격자는 펼칠 때 계산하고 DOM을
만든다. 진행 기록도 접힌 루프에는 날짜를, 접힌 날짜에는 개별 기록을 만들지 않는다.

지침 A/B/C/E는 첫 펼침 때 게임 시작 상태로 한 번 계산해 시나리오별 세션 LRU 캐시에
저장한다. D만 공개 이력을 읽으므로 지침을 펼친 렌더에서 다시 계산한다. 지침 자체가
접혀 있으면 A~E와 D 모두 계산하지 않고 `펼쳐서 계산`만 표시한다. 이 캐시 역시
localStorage에는 저장하지 않는다.

1차 개선 커밋과 현재 코드를 동일한 합성 P9 상태에서 각각 새 390×844 문서로 3회
측정했다. 관측 수와 못된 고양이 카운터 조건은 기존 증가 측정과 같은 43/58/73개로
맞췄다. 아래 수치는 중앙값이며, 이 쌍 비교는 2·3차 변경의 순효과를 보기 위한 별도
통제 측정이라 위의 실제 진행 절대값과 섞지 않는다.

| 현재 루프 | 관측 | 1차 개선 렌더 | 2·3차 렌더 | 변화 |
|---:|---:|---:|---:|---:|
| 3 | 43 | 367.7ms | 335.4ms | -8.8% |
| 4 | 58 | 599.9ms | 562.5ms | -6.2% |
| 5 | 73 | 943.7ms | 893.1ms | -5.4% |

| 현재 루프 | DOM 원소 1차 → 2·3차 | 변화 | HTML bytes 1차 → 2·3차 | 변화 |
|---:|---:|---:|---:|---:|
| 3 | 2,650 → 365 | -86.2% | 170,386 → 23,494 | -86.2% |
| 4 | 2,860 → 369 | -87.1% | 186,676 → 23,725 | -87.3% |
| 5 | 3,070 → 373 | -87.9% | 202,955 → 23,956 | -88.2% |

접힌 DOM은 루프당 4개만 늘어 사실상 일정해졌다. 역할·범인 본문, 두 격자, 날짜별
진행 기록 항목은 모두 0개인 것을 측정 문서에서 확인했다. 따라서 3번의 DOM 제곱
증가는 제거됐다. 그러나 렌더는 3→4루프 1.68배, 4→5루프 1.59배로 여전히 선형이
아니며 5루프 893.1ms로 200ms 목표를 넘는다. 접힌 화면에서도 정확한 룰 후보와 현재
P9 예고를 위해 현재 상태 역할표를 계산하는 경로가 남아 있기 때문이다. 다음 범위는
요청에서 제시한 4번, 즉 현재 역할표 내부의 관측별 원인 후보·교집합·조건부 전파를
분해하고 증분 교집합/역할별 분리/공집합 조기 종료 중 효과가 확인된 방법을 적용하는
것이다.
