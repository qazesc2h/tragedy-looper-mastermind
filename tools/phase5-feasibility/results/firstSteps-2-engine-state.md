# Section 2 engineStateKey 재계측 — `firstSteps:2`

> 후속 목적지 계측이 전체 P2의 P4 상태 수를 확정했다. 이 문서의 12,062개는 한 P2
> 부모의 probe이며 전체 상태 수가 아니다. 전체 수치와 갱신 판정은
> `firstSteps-2-p4-destinations.md`를 따른다.

- 실행일: 2026-08-20
- 각본: The First Script (NT), 3일 × 3루프, 캐스트 6명
- 기준 커밋: `892f9bf`
- engine schema: `phase5-engine-v1`
- transition schema: `headless-transition-v2`
- 검색 정책: `worst-legal-response` (정책 상태 키 없음)
- 진단 정보 문맥: `perfect-recall`
- 적용 프로필: pilot 4 GiB / 10 GiB / 30분 / 상태 500만 / 전이 5천만

## 결론

공개 trace를 엔진 키에서 분리하면 **P4 해결 뒤 물리 병합률은 96.728%**다. 작은
2일 36경로 감사의 97.22%와 같은 규모의 병합이 한 P2 부모의 전체 368,640개 합법 P3
대응에서도 확인됐다.

그러나 해결 전 P2×P3 합법 대응 간선은 정확히 23,357,030,400개다. 아직 놓인
`(owner, card, target)`은 P4 효과를 계산하는 현재 전이 상태이므로 엔진 키에서도
버릴 수 없다. 승인된 “다음 계층 1억 초과 시 생성 없이 중단” 조건에 걸려 전체
P2 부모의 P4 후속 상태 수는 세지 않았다. 따라서 현재의 명시적 전이 열거기로 완전
opening book을 만드는 판정은 여전히 불가다.

카드가 공개되면 368,640개 공개 문맥은 모두 달라지지만, 물리 결과는 12,062개로
합쳐진다.

## 무엇이 줄고 무엇이 남는가

- 줄어드는 것: 해결 뒤 물리 보드·자원·지속 효과가 같은 후속 상태와 그 전이 계산
- 남는 것: 모든 합법 행동 라벨과 P4 전에 효과를 결정하는 현재 배치
- 별도 관리: full 공개 trace와 disclosure preview의 정보 누출·시그널링 평가

기본 최악 대응 검색은 같은 물리 상태에서 합법한 모든 대응을 비교하므로 공개 이력을
읽지 않는다. 이 덕분에 엔진 전이 캐시는 병합할 수 있다. 반면 실제 주인공의 대응
예측과 시그널링 효과는 잃는다. 이 교환은 확률적 예측 없이 “어떤 대응이 와도”의
보수적 관계를 제시하려는 명세에는 적합하다. 정보 누출은 별도 축으로 병기해야 하며
물리 탐색 결과와 숨은 점수로 합치면 안 된다.
