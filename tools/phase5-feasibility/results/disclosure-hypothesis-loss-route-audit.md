# 정보 누출·가설 공간 감사와 패배 경로 회귀 벡터

- 날짜: 2026-08-21
- 범위: 지시 3·4 (`disclosure-preview`, 패배 관측 가설 필터, 대표 위험 경로)
- 기준: `distanceToLoss()`의 종착 조건과 `routes`를 서로 다른 계층으로 취급

## 결론

`distanceToLoss.routes` 도입 때문에 정보 누출 예고나 가설 공간이 잘못 좁아지는
회귀는 없었다. 142개는 번들 각본에 실제로 들어 있는 **종착 패배 조건** 수이고,
224개는 그 종착점으로 가는 **각본가만 아는 물리 경로** 수다. 공개 관측 가설 필터는
후자를 직접 읽지 않는다.

`disclosure-preview.ts`에서 `distanceToLoss()` 호출은 선택형 패배 조건 하나를
`key`로 찾는 곳 한 군데다. 여기서 읽는 값은 `activation`과 공개 종료 timing을 고르는
`category`뿐이며, `remaining`, `requirements`, `routes`는 읽지 않는다. 화면의 정보
누출 예고도 “가까워진 거리”를 표시하지 않고, 패배가 공개됐다고 가정했을 때 남는 룰
조합 수·확정 역할·설명 가능한 공개 조건만 표시한다.

`hypothesis.ts`는 `distanceToLoss()`를 참조하지 않는다. 공개 종료 시점의 보드,
공개된 사건 발생, 종료 timing으로 `plot:*`, `role:*`, `incident:hospitalIncident` 같은
공개 설명을 구성한다. 예를 들어 청부업자가 핵심 인물을 죽였어도 주인공 관점의 패배
설명은 `role:keyPerson`이고, 숨은 경로 키 `death:killer:*`는 가설 필터에 들어가지 않는다.
224개 경로를 공개 조건 224개로 바꾸면 실제 역할과 범인을 가설 필터에 주입하므로
정보 누출이 된다.

## 과잉 배제 검사

기존 공개 관측 회귀에 다음 실제 번들 각본 종료 경로를 추가했다.

| 각본 | 실제 엔진 경로 | 종료 관측 | 실제 룰 조합 |
|---|---|---|---|
| `basicTragedy:2` | 연쇄 살인마가 핵심 인물 살해 | `effect` | 후보에 남음 |
| `basicTragedy:4` | 살인 청부업자가 핵심 인물 살해 | `effect` | 후보에 남음 |

두 테스트 모두 실제 역할 훅, 사망 배치, 즉시 종료, `finishLoop()`의 공개 스냅샷을
거쳐 `lossObserved`를 만든 뒤 가설을 다시 계산한다. 실제 조합 배제는 0/2였다.
기존 회귀의 봉인된 것, 청부업자 주인공 사망, 연인A, 시간 여행자, 병원 사건과 함께
공개 패배 관측의 대표 계층을 고정한다.

정보 누출 예고에는 같은 선택형 청부업자 패배에서 핵심 인물 살해 경로의 진척만
0→충족으로 바꿔도 결과 전체가 동일하다는 회귀를 추가했다. 공개 설명에는
`role:killer`만 남고 `death:killer:*`는 나타나지 않는다.

없는 역할이므로 다른 역할의 경로 카드에 인위적으로 표시하지 않고 실제
`killCharacter()` 진입점에서 생존을 검증한다.
