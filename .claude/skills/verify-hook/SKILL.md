# 훅 구현 검증

`src/impl/` 의 훅 하나를 놓고 **구현이 `source` 문장을 벗어나지 않았는지** 확인한다.

이 프로젝트에서 가장 흔한 결함은 버그가 아니라 **원문에 없는 조건을 추가하는 것**이다.
컴파일도 되고 테스트도 통과하지만 규칙이 틀린다.

## 절차

대상 훅마다 아래를 순서대로 수행하고, 각 항목에 ✓ / ✗ / ? 를 매긴다.

### 1. 원문 인용

`source.prerequisite` 와 `source.description` 을 **그대로** 출력한다.
요약하거나 번역하지 않는다.

### 2. 대응표 작성

| source 조각 | 구현 위치 | 코드 |
|---|---|---|
| (원문 한 조각) | `when` / `effect` | (해당 표현식) |

원문의 모든 조각이 표에 나타나야 한다. 남는 조각이 있으면 구현 누락이다.

### 3. 역방향 검사 — 가장 중요

**구현에는 있는데 원문에 없는 조건을 찾는다.**

`when` 의 모든 논리항을 하나씩 짚으면서 "이 조건이 원문 어디에서 왔는가"를 묻는다.
근거를 못 대는 항이 하나라도 있으면 그것이 환각이다. 제거하거나 질문으로 올린다.

흔한 환각:

- 원문에 없는 생존 확인 (`alive` 체크)
- 원문에 없는 장소 일치 확인
- 원문에 없는 "1루프당 1회" 제한
- 원문에 없는 상한/하한
- 다른 역할의 조건을 끌어옴

### 4. 표현 정밀도

| 원문 | 올바른 구현 | 흔한 오구현 |
|---|---|---|
| `at least N` | `>= N` | `> N` |
| `N or less` | `<= N` | `< N` |
| `other character` | 자신 제외 | 자신 포함 |
| `character` | 생존자만 | 시체 포함 |
| `card` | 생사 무관 | 생존자만 |
| `this character's location` | `board[self].at` | 시작 장소 |
| `You may` | `kind: "optional"` | 강제 실행 |

### 5. 프로젝트 규약

- [ ] 역할 조회에 `effectiveRole(state, char)` 를 썼는가 (`scenario.cast` 직접 참조 금지)
- [ ] 장소 X 참조에 `resolvePlaceX(state)` 를 썼는가
- [ ] `source` 필드를 지우거나 고치지 않았는가
- [ ] `kind` 가 원문의 `You may` / 강제 표현과 일치하는가

### 6. 테스트 존재 확인

훅마다 최소 2개가 있어야 한다.

- `prerequisite` 를 만족하는 케이스 → 효과가 적용됨
- 만족하지 않는 케이스 → 아무 일도 없음

경계값이 있으면(`at least 2` 등) 경계 바로 아래 케이스를 추가한다.

## 출력 형식

```
## <역할 id> / 훅 <n>

원문:
  prerequisite: ...
  description: ...

대응표:
  ...

역방향 검사:
  ✓ 모든 조건이 원문에 근거함
  또는
  ✗ `state.loop.board[self].alive` — 원문에 생존 조건 없음. 제거 필요.

정밀도: ✓
규약:   ✓
테스트: ✗ 경계 케이스 누락 (음모 1개인 경우)

판정: 수정 필요
```

## 모호할 때

원문이 두 가지로 읽히면 **판정을 유보하고 `QUESTIONS.md` 에 추가한다.**

```md
## Q<n>. <역할> — <쟁점>
- source: "<원문 그대로>"
- 해석 A: ...
- 해석 B: ...
- 현재 A로 구현. 실물 설명서 확인 필요.
```

추측으로 판정하지 마라. 유보된 항목이 쌓이는 것이 잘못 통과시키는 것보다 낫다.
